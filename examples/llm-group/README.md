# LLM 子评估器端到端示例

本例创建一个包含相关性（40%）、准确性（40%）、合理性（20%）的 LLM 评估器，
整组保存并发布，再将一个本地模拟 Agent 的合成样本交给 DeepSeek 官方
`deepseek-v4-pro` 分别评分。每个子项有独立模型配置、提示词、评分与 JudgeRecord；
父项只进行加权汇总，不再调用模型，也不会重复计入任务总分。

## 复现与恢复查询

先启动本工程的 API、Worker、模拟 Agent 目录和 Trace 服务。模型凭据只保存在本机服务配置中；
本目录和脚本不保存、读取或输出密钥。`group.json` 只保存模型引用和评估配置。

在工程根目录执行，会创建新评估器和任务，正常情况下产生三次真实评审请求：

```sh
.venv/bin/python examples/llm-group/run.py
```

默认 API 为 `http://127.0.0.1:18097`，仅支持本机行外模式，使用合成 Token `local`。
行内模式请从已登录页面提交，沿用行内 Agent 目录和真实会话 Token。

仅核对已保留的执行，不创建资产或发起新模型请求：

```sh
.venv/bin/python examples/llm-group/run.py \
  --group-id e9d657db-d59c-4c00-b742-8dcdbcce706b \
  --resume-run 7a9d8589-80b0-471d-9fc4-da540c8f96ad
```

仅指定 `--group-id` 会用该评估器的当前发布版本发起新任务，因此不能使用上述已删除实例；
重新执行不带此参数的创建命令可生成新的可用实例。`--output PATH` 可另存摘要。
脚本先保留创建的 ID，再等待执行结果；遇到超时或网络问题，请使用原 Run ID 恢复查询，避免重复提交。

脚本复用 `../llm-conciseness/dataset.json` 的第一条样本，已存在时核对内容指纹而不覆盖。
通过标准包含任务完成、父子精确版本匹配、每个子项真实响应与请求指纹、模型引用一致、
父项加权结果正确。错误、缺失分数或未完成均返回非零退出码。

离线验证这些成功/失败判断：

```sh
.venv/bin/python examples/llm-group/test_run.py
```

`frontend/tests/fixtures/llm-group-report.json` 是本次合成样本的报告快照，已检查不含模型密钥，
用于独立测试环境中的任务配置、综合分和子项结果界面回归。
