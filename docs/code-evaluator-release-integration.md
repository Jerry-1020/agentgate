## 保留与新增

- 保留 release 的任务重跑、行内/行外路由、样本并发、团队限流及执行事件。
- 保留 release 的样本等权综合分口径，不另设 Code 分数权重。
- 将 Code 实现注册到现有评估器执行链；不引入新服务、队列或存储表。
- 任务表单允许不依赖样本内置 expectations 的 Code 规则；旧内置规则仍执行原校验。
- Code 弹窗复用 EvaluatorTaskHistory，按发布版本查看关联测评历史。
- 新建时自动生成独立指标标识；指标和失败影响收在高级设置，已有定义保持原值。
- 新建的预置选项来自系统当前展示的内置规则目录，不另设模板目录。
  支持复选，多个模板合并为一份可编辑 Python；全部检查通过得 1 分，否则得 0 分，各项说明合并、证据去重。
  组合以目录中首个选中模板的维度归类，任一模板为 blocking 时沿用阻断检查，均可继续修改。
  “不使用预置模板”与具体模板互斥，清空选择可恢复原自定义定义；生成后保存的是最终源码，不反向恢复模板选择。
  选中后按原规则类型生成可编辑 Python 起始代码，并带入原维度和失败影响；使用独立指标保存为 Code 草稿。
  起始代码采用显式工具名/字段/期望值，不等同于内置评估器对全部 expectations 和算子的完整支持；评分以用户保存的代码为准。
  “不使用预置模板”进入自定义 Python，切换时暂存自定义代码，返回时恢复。
  用户手填名称/描述保留，覆盖已修改配置需确认；原预置评估器不被修改。
- 移除常用示例、示例代码、语法速查及快捷条件生成入口；保留代码编辑、测试数据及语法检查。
- Python 和 JSON 使用同一编辑组件及配色，均显示行号，按语言高亮；发布版本的代码保持只读。
- 右侧标题栏选择智能体、分支、版本、Trace，自动填充脱敏测试副本；Python 与 JSON 编辑器并排，标题栏等高、输入框均固定 360px 并内部滚动，试运行独立放在编辑区下方。窄屏改为上下排列。
- 运行时错误保持 ERROR 和空分数，release 执行流程中记录 evaluator 失败事件。

## 保持不变的首版限制

- 保存最终源码，不保存或反向恢复条件表单。
- 测试 JSON 来自所选完整历史 Trace 的脱敏副本，允许继续编辑；不再从测评集构造测试数据。
- 试运行复用受限子进程及证据 ID 检查，不调用 Agent、不创建任务、不保存测试数据；
  每个 API 进程最多同时接受两个试运行，繁忙返回 429。
- 静态检查不执行代码；试运行的分数仅针对手动输入，不代表真实 Agent 质量。
- output_only 证据的 Code 检查为不适用，包括只检查回答的自定义代码；新规则按整条 Trace 判断，旧规则仍按轮判断。
- 源码 16 KiB，源码加输入 JSON 1 MiB，单次执行 3 秒、20,000 步；
  容器和字符串取值上限 4,096，超限不截断证据而是报告异常。
- 同时启用多个重复规则会参与现有综合分计算，配置时避免无意重复计权。

## 2026-11-05：完整 Trace 测试与原生规则输入

- 测试来源仅保留 Trace，不再显示来源选择、自定义选项或整条 Trace 评分提示语；选中 Trace 后自动填入测试副本。手动修改后的数据在切换 Trace 时通过页面内提示确认替换；不再显示重新载入/刷新按钮及重复来源说明。
- 右侧编辑器头部采用智能体、分支、版本、Trace 四个选择框；无轮次选择。两个编辑器固定 360px、内部滚动、头尾对齐；窄屏上下排列。
- 首版仅查询当前团队在 AgentGate 中已保存的 Agent Trace，按已知执行适配器区分行内/行外；不调用外部智能体目录、Trace Server 或 Agent。
- `GET /api/evaluators/code/trace-targets` 和 `/code/traces` 在数据库端关联运行与轨迹，分页返回元数据，不把完整运行清单和 Trace 正文带到列表页面。
- `GET /api/evaluators/code/trace-data` 校验团队和模式后，返回整条轨迹的脱敏副本。JSON 字符串内的敏感字段也脱敏；超大输入明确拒绝，不截断证据。
- 新规则配置增加 `input_format: trace-v1`，入口 `def exec_evaluation(trace):`。保留原生 `trace_id/run_id/case_id/spans/turn_outcomes/final_output/final_state`。SDK 已记录的本轮输入补入 `turn_outcomes[turn_id].input`；缺失时为 null，不从测评集伪造。
- 新规则走现有 case evaluator 执行分支，对整个样本只评分一次，`check.turn_id = null`，允许关联跨轮 span。有 Agent 执行异常返回 ERROR；output_only 证据不足返回不适用。
- 原配置未带 input_format 的已发布规则继续使用原有 turn_data 与按轮执行方式。旧规则的测试生成仅接受单轮历史 Trace，多轮会明确提示，避免静默改变评分范围。
- 不改数据库表结构、不改历史 manifest 或评分。新前端、API、worker 必须一起升级；回滚旧版程序前应停用新格式规则，旧程序不认识新配置。试运行用脱敏副本，正式任务用真实规范化 Trace，因此涉及脱敏字段的规则可能得到不同结果。
