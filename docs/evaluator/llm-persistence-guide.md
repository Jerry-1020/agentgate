# LLM 评估器：保存、发布与按版本运行

更新日期：2026-10-16。

## 子评估器操作闭环

新建的 LLM 评估器现在是一组独立子评估器的容器。评估器保存名称、备注描述、启停状态、创建日期和更新日期；已发布内容显示版本号。日期是评估器身份的创建/更新时间，没有新增独立的发布日期字段。

LLM 评估列表仅展示 **回答质量综合评估** 这一预置模板及已有自建评估器。模板卡片沿用规则评估器的白底、浅绿标签、深色标题及底部文字操作，展示四个子评估器及权重；首页与新建弹窗卡片统一尺寸，小屏幕下按可用宽度收缩。列表可按模板名称或子项名称搜索。首页卡片仅提供 **查看详情**，可只读切换查看各子项的权重及完整提示词，不创建或保存配置。需要使用时进入 **新建 LLM 评估器** 应用模板，配置并发布后生成可用于任务的自建评估器。父评估器名称与备注输入框采用相同的单行高度。

2026-10-16 已按用户要求清理本机原有 7 个 LLM 实例，目前首页只剩上述模板。
已发布 LLM 实例通过 `DELETE /api/evaluators/{id}` 删除时，服务端归档并停用该身份，
不再出现在目录或新任务选择中，也不能再次编辑、发布或启用。原版本、子项及测评任务结果保留，
仍可按历史精确版本读取；这与下文的“删除草稿”是两个操作。

1. 进入 **评估器 → LLM 评估 → 新建 LLM 评估器**，初始窗口展示综合评估器模板。预置的 **回答质量综合评估** 包含简洁性 10%、相关性 30%、准确性 40%、合理性 20% 四个子评估器；点击 **使用此模版创建** 一次生成整组可编辑配置，该按钮与右上角 **自定义创建 LLM 评估器** 共用绿色主按钮样式。父评估器名称、备注和子项均可修改；也可选择 **自定义创建 LLM 评估器** 从空白配置开始。新建模板窗口比原窗口增高约三分之一，小屏幕下不超过视口的 92%。
2. 左侧 **新增** 直接创建并选中一个空白子评估器，不再弹出模板窗口。每个子项旁都提供 **删除** 按钮，确认后从当前表单移除，保存草稿后生效；删除其他子项不会打断当前子项编辑。同一组至少 1 个、最多 32 个子评估器。
3. 切换左侧子评估器，在右侧配置各自的名称、备注、模型、System Prompt、可选 User Prompt 和通过分数。底部变量提示实时合并 System/User Prompt 中的 `{{变量名}}`，去除首尾空格并按首次出现顺序去重；没有非空变量名时隐藏整行，清空、移除 User Prompt 和切换子项会同步更新。执行仍支持 `{{input}}`、`{{output}}`，其他变量沿用保存校验；凭据继续由服务端配置提供，页面和保存载荷中不包含 API Key。
4. 模板选择仅保留 **回答质量综合评估**。简洁性、相关性、准确性、合理性作为综合模板内部子项保留，提示词可直接编辑或清空；子项及历史单体编辑器均不再提供独立子模板选择入口。
5. 每个子评估器权重须大于 0，合计为 100%；可点击均分权重。综合通过分数和各子评估器的通过分数分别配置，范围均为 0—1。
6. **保存草稿** 一次保存父评估器、全部子评估器配置和权重。重新打开页面可恢复已保存内容。保存使用草稿 ID、更新时间校验；另一窗口已保存新内容时，旧窗口会收到冲突提示，不覆盖新草稿。
7. **发布并启用** 在后端先验证每个子评估器的配置和模型引用，再一次性发布整组。父版本固定各子版本及权重，并整体启用。任意校验失败都保留整组草稿，不生成部分可用版本。保存、发布不会调用模型；真实连接以任务执行为准。
8. 测评任务只选择父评估器。提交后运行快照同时保存父版本和全部子版本，子项作为执行依赖；任务总分统计父评估器一次。样本结果可展开查看每个子评估器的得分、权重、理由及原始模型评估记录。
9. **编辑新版本** 创建下一份草稿；已有草稿时进入该草稿。**版本历史** 读取指定父版本及其当时固定的子配置。之后修改名称、Prompt、权重或移除子项，都不改变历史版本与任务。
10. **删除草稿** 同样校验草稿 ID 和更新时间。尚未发布的评估器会整体删除；已有发布版本则只删除草稿。移除子项时清理未发布子数据，已发布子版本继续服务历史查询和任务。

各子评估器都是独立模型请求。`llm_group@1` 只组合子评估器结果，不额外调用模型：

- 综合分数为 `Σ(适用子得分 × 权重) / Σ(适用子权重)`，原始分数范围 0—1，报告可显示 0—100 分。
- 不适用子项不参与总分，其余权重重新归一化；全部不适用时父结果也不适用。
- 任一子项执行出错，父结果为错误且没有总分，其他子项的独立结果及错误信息仍保留。
- 阻断性失败优先；否则任一子项待复核会传递为父级待复核。其他情况下根据综合通过分数判定通过或失败。
- 一个普通子项低于自身通过分数，不会直接覆盖父评估器的加权总分判定。

子评估器归属于父评估器，不能单独出现在目录选择项、独立选入任务或被另一评估器接管。暂不支持嵌套子评估器组。旧 `answer_quality@1` 单体评估器和 `answer_quality@2` 单次请求的多维度评估器继续保留，已有任务仍按原快照执行。

## 子评估器接口与事务

| 操作 | HTTP 接口 | 结果 |
| --- | --- | --- |
| 创建组草稿 | `POST /api/evaluators/llm-groups` | 原子创建父身份、子身份及整组草稿 |
| 读取当前组 | `GET /api/evaluators/{id}/llm-group` | 优先返回草稿，否则返回最新发布内容 |
| 读取历史组 | `GET /api/evaluators/{id}/llm-group?version=N` | 返回父版本及其固定子版本 |
| 保存组草稿 | `PUT /api/evaluators/{id}/llm-group/draft` | 原子替换整组草稿，校验预期草稿版本 |
| 发布并启用 | `POST /api/evaluators/{id}/llm-group/publish` | 原子发布全部子版本及父版本，并整体启用 |
| 删除组草稿 | `DELETE /api/evaluators/{id}/llm-group/draft` | 校验预期草稿版本后删除，保留已发布历史 |

保存已有草稿、发布和删除均携带 `expected_draft_id` 与 `expected_draft_updated_at`。从历史发布版创建草稿时，保存请求携带 `based_on_version`；创建新的评估器不携带旧版本信息。版本列表仍使用 `GET /api/evaluators/{id}/versions`。只有已发布父评估器可以启用或停用，停用阻止新任务选用，不改变历史任务执行。

所有父子记录保存在原有 Evaluator 表中，SQLite 与 MySQL 使用相同事务约定，无新的浏览器持久化副本或数据表。存储层还会比较父身份更新时间，阻止保存过程中发生的元数据竞争；跨团队或不同父评估器的子项不能混入整组操作。

## 历史单体评估器的编辑与运行

以下流程继续适用于目录中已有的独立 Prompt 评估器。新版“新建 LLM 评估器”入口使用上述子评估器组流程。

1. 进入 **评估器 → LLM 评估**，打开已有的单体评估器。单体 Prompt 编辑器及多维度编辑器仍按原配置类型打开。
2. 填写名称、说明，选择后端已接入的评审模型。填写提供商和模型引用不会自动接入一个新服务；API Key 仍由服务端环境提供。
3. 直接编辑 System Prompt，可添加 User Prompt；点击 **清空** 会清除 Prompt。历史单体编辑器不再提供模板选择，原有已保存提示词保持不变。支持 `{{input}}`（全部轮次输入）和 `{{output}}`（实际最终输出），其他变量会在保存/发布校验时拒绝。名称最多 50 字，描述最多 200 字。高级配置可调整 0—1 通过阈值。
4. 点击 **保存**。成功后显示“草稿已保存到服务器”，草稿卡片会留在目录中。刷新页面并再次打开详情，应能恢复名称、描述、Prompt、模型和阈值。
5. 点击 **发布并启用**。后端验证实现、配置及已注册模型提供商后，发布不可变 v1 并启用。仅保存草稿不能创建测评任务。发布验证不等于真实模型连接测试；模型可用性以实际运行结果为准。
6. 点击 **打开测评配置**，配置被测 Agent、测评集及执行设置，勾选此评估器。选择项显示发布版本。提交时发送明确的评估器 ID 和版本，任务保存完整配置快照。
7. 完成任务后，在 **任务详情 → 任务配置**（评估器配置区）查看当时的版本、模型、提示词和阈值。在样本的 **评估结论与依据 → 原始评估记录** 中查看实际请求、响应、0—1 原始分数、置信度和理由（报告汇总可能显示为 0—100 分）。
8. 回到评估器详情，点击 **创建新版本草稿**，修改提示词并保存。已有 v1 与历史任务保持不变；再次发布得到 v2。
9. 点击 **版本历史 → 查看 v1** 检查旧版本。历史版本只读；基于历史版本编辑仍进入独立草稿。已有草稿时优先打开该草稿，避免覆盖未发布内容。

部署本次代码后，API 和任务 Worker 都需加载新代码，才能共同识别 `llm_group@1` 及其依赖配置。已有进程应按原部署方式重启；此文档不改变服务端模型连接、数据库和登录配置。

## 历史单体评分语义

页面中的发布版本 v1、v2 是某个评估器的内容版本；执行实现 `answer_quality@2` 表示多维度评分协议，两者不同。

- Prompt 评估器使用 `answer_quality@1`：System Prompt 对应 `config.instruction`，可选 User Prompt 对应 `config.user_prompt`，`config.render_template=true` 启用变量替换；现有严格 JSON 得分/原因契约由系统追加。历史配置缺省不替换变量，避免改变旧提示词。新建子评估器复用这一配置契约。
- 输入输出先脱敏、限长再进行一次变量替换；输入中的占位符不会递归展开。重复变量和附加证据共享输入预算。
- 已有 `answer_quality@2` 多维度评估器继续使用原维度编辑器，一次模型请求携带所有维度提示词和按范围选取的实际执行证据。
- 模型必须为每个维度返回 `id`、`score`、`confidence`、`reason`、`review`。分数与置信度范围均为 0—1；不得缺失、重复或加入未知维度。
- 后端计算 `总分 = Σ(维度分数 × 权重 / 100)`，页面显示为 0—100 分。模型不决定加权总分。
- 任一维度要求人工复核，或置信度低于配置阈值，整体结果为待复核；否则按总分和通过阈值判定。
- 无最终输出时为不适用；超时、截断或非法响应不能视为通过。非法协议最多纠正一次，并保留请求、响应及纠正记录。
- `answer_quality@1` 的整体评分协议与历史任务保持可执行；缺省 User Prompt 使用原证据提示。编辑旧整体评估器保留其评分标准、范围与执行参数。

## 单体持久化与任务引用

复用现有 Evaluator Catalog，没有增加浏览器持久化副本或另一套数据库：

| 操作 | HTTP 接口 | 结果 |
| --- | --- | --- |
| 首次保存 | `POST /api/evaluators` | 创建身份和服务端草稿 |
| 修改名称、说明 | `PATCH /api/evaluators/{id}` | 更新显示元数据 |
| 保存已有草稿 | `PUT /api/evaluators/{id}/drafts/current` | 替换草稿配置 |
| 重新进入页面 | `GET /api/evaluators/{id}` | 读取当前草稿和最新发布版本 |
| 创建新版本草稿 | `POST /api/evaluators/{id}/drafts` | 从明确的发布版本创建草稿 |
| 发布 | `POST /api/evaluators/{id}/drafts/publish` | 原子生成不可变版本，移除草稿 |
| 启用 | `PATCH /api/evaluators/{id}`，`enabled=true` | 允许新任务选用 |
| 版本历史 | `GET /api/evaluators/{id}/versions` | 读取已发布内容及指纹 |

普通任务、本地贷款、平台任务、平台 A/B 和稳定性任务贯通 `evaluator_refs`；原 A/B 路径沿用其既有精确版本字段。A/B 两侧固定同一组版本；预约和重跑沿用保存的运行快照。草稿、不存在的版本和停用评估器不能用于新任务。

行外目录使用 `localAgentDirectory`、合成 Token `local`；行内使用 `agentDirectory` 和真实会话 Token。本次没有改变该分流。

## 故障处理

- 保存失败：保留编辑内容，显示真实错误，不显示保存成功；修复连接后重试。
- 发布失败：保留草稿，显示后端校验错误，不会创建可用的假版本。
- 单体评估器发布成功而启用失败：页面明确说明已发布版本，刷新后可点击“启用”。子评估器组的发布与启用在同一事务内完成。
- 保存期间禁用编辑、重复提交和关闭；离开未保存的修改需确认。

## 简洁性模板与真实执行实例

简洁性模板保留用户提供的完整中文评分标准，点击应用后可以编辑。模板库同时提供相关性、准确性和合理性；这些都是可编辑的评分提示词，不能代替模型实际执行结果。

可复现数据集、任务执行脚本与结果保存在 [简洁性示例](../../examples/llm-conciseness/README.md)。真实验证使用本地模拟 Agent 的实际执行轨迹与官方 DeepSeek 评审；被测输出的模拟来源会明确保留。评审连接、API Key 与运行数据库不随源码分发。

DeepSeek 官方接口支持 `AGENTGATE_JUDGE_OUTPUT_TOKEN_FIELD=max_tokens` 与 `AGENTGATE_JUDGE_THINKING=disabled`。连接参数放在私有环境文件；API 与 Worker 应使用相同配置。
