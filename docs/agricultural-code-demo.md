# 农贷：预置与自定义规则组合演示

本演示使用现有本地 Loan Agent 和合成数据，不改变 Agent 行为。亩均 3000 元及受灾转人工均为说明用途的模拟规则，不代表真实信贷政策。

## 组合与作用

- 预置「必需工具调用」：检查是否调用 credit_inquiry。
- 预置「最终状态」：按原通用逻辑验证低风险 approved、高风险 pending_review。
- 自定义「农贷演示 · 亩均额度复核」：申请金额超过种植亩数 × 样本演示亩均额度时，必须调用 request_human_review，最终 human_review=True 且 approved=False。
- 自定义「农贷演示 · 受灾农户复核」：disaster_affected=True 时，必须调用人工复核，最终 human_review=True 且 approved=False。

两条自定义规则同时检查业务输入、工具证据、最终状态。未触发专项条件得 1 分；触发却未复核得 0 分；必要输入字段缺失报 ERROR，不当成通过。

## 实际组合结果

所有样本均为 20 亩，演示额度为 60,000 元。

| 样本 | 输入 | 预置两项 | 亩均复核 | 受灾复核 | 样本分 |
|---|---|---|---|---|---|
| 正常农资申请 | 50,000 元、未受灾、低风险 | 通过 | 通过 | 通过 | 100 |
| 额度超限 | 80,000 元、未受灾、低风险 | 通过 | 失败 | 通过 | 75 |
| 受灾申请 | 50,000 元、受灾、低风险 | 通过 | 通过 | 失败 | 75 |
| 已转人工 | 80,000 元、受灾、高风险 | 通过 | 通过 | 通过 | 100 |

现有 Agent 仅按通用 risk 字段决定是否复核，不识别亩均额度或受灾条件。这正是两条自定义规则检出的业务缺口；没有修改 Agent 来迎合评分。

本地实际任务：bddde71b-aa7e-468e-88fd-579372892aa8。综合分 87.5，16 项检查中 14 项通过、2 项预期失败、0 项运行异常。正式本地 Celery 任务已完成。

## 代码与复现

脚本 `scripts/demo-agricultural-code.py` 包含两段完整可编辑 Python、四个样本，以及通过现有 API 创建、发布、启用和提交任务的步骤。每次运行都会创建新的演示数据，仅限本地 8200 API，不自动预置到生产。

独立组合回归：`tests/test_agricultural_code_demo.py`，验证精确失败项、综合分与 span 证据关联。与 Code 评估回归共同运行，覆盖发布冻结、执行异常与证据关联。


## 原生 Trace 示例：人工复核与自动批准互斥

`scripts/demo-agricultural-code.py` 的 `HANDOFF_SOURCE` 可复制到新建规则评估器。
它使用 `exec_evaluation(trace)`，检查整个样本的所有轮次：同一申请只要转人工，就不应同时出现自动批准；未转人工时不触发互斥检查。本规则不替代「必须转人工」检查，不区分动作先后，仅用于合成演示。

| 场景 | 必需工具 / 最终状态 | 自定义规则 |
|---|---|---|
| 单轮普通申请，仅自动批准 | 通过 / 通过 | 100 分，不触发互斥检查 |
| 单轮高风险申请，仅转人工 | 通过 / 通过 | 100 分 |
| 两轮先转人工、后自动批准 | 通过 / 通过 | 0 分，动作冲突 |
| 两轮先自动批准、后转人工 | 通过 / 通过 | 0 分，动作冲突 |

本地任务 `927cc2bb-3638-477c-ac67-38e64af9069b`：4 个样本、3 个评估器，12 个结果中 10 通过、2 个预期失败、0 个运行异常，综合分 83.3。自定义结果均为用例级单次评分，跨轮证据关联完整；4 个历史 Trace 的试运行与正式结果一致。

独立回归还覆盖重复转人工与乱序 spans，不依赖数组排列。测试数据、任务和评估器仅写入本地演示库，不作为生产初始化数据提交。
